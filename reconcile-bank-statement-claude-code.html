How to reconcile a bank statement with Claude Code (without letting the AI do the maths)

2026-09-20

Asking a chatbot to "reconcile my bank statement" usually ends one of two ways: it produces a confident-looking answer that is subtly wrong, or it runs out of patience halfway through a long list. The reason is simple. Language models are good at reading and explaining, and unreliable at adding up hundreds of amounts and remembering which lines they have already used.

The fix is to split the job. A small script does the matching and the arithmetic deterministically. Claude does what it is actually good at: looking at the leftovers, explaining them, and drafting the paperwork.

The workflow

  1. Export two CSV files: the bank statement and the ledger (your books) for the same period. Keep the originals untouched and work on copies.
  2. Run a matcher that pairs lines by amount (to the cent) within a few days of each other, preferring the closest description and date.
  3. Let it find the harder matches: one bank payment that covers several invoices (a split), and one deposit in your books that is really several bank lines (a batch).
  4. Read what is left over: lines only on the bank statement, and lines only in your books.
  5. Have Claude classify each leftover, propose an action, and write the report. You approve.

Try it on sample data (2 minutes)

There is a free, MIT-licensed reconciliation skill for Claude Code with sample data for a fictional studio. Clone it, open Claude Code in the folder, and ask:

Reconcile sample-data/bank_statement_2026-09.csv against sample-data/ledger_2026-09.csv

You should get an unreconciled difference of 332.60, one split match, one batch match, and five unmatched lines. If you do, the tooling works on your machine.

Rules that keep it trustworthy

  • The model never adds up money. Every total comes from a script that uses exact decimal arithmetic.
  • Originals are never modified. Work in a copy, write reports to a separate folder.
  • Say what you cannot see. If the cause of a difference is not in the data, the report should say so rather than invent one.
  • Drafts, not postings. Suggested journal entries are proposals for a person to approve.

Limits

This approach matches on amount, date window and description similarity. It does not convert currencies, and lines whose amounts differ between bank and books (for example fees netted from a payout) will appear as unmatched. That is deliberate: an honest "unmatched" beats a forced match. This is a workflow aid, not accounting, tax or legal advice.
