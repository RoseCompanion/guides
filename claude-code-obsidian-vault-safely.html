Using Claude Code with an Obsidian vault safely: 7 rules that protect your notes

2026-09-22

An Obsidian vault is a folder of plain text files, which makes it easy for an AI assistant like Claude Code to read and edit. That is also the risk: a confident assistant with write access to years of notes can do a lot of quiet damage in a minute. These are the rules that make it safe enough to use.

1. Back up first, every time

Copy the vault or make a git commit before any batch change. Notes are irreplaceable; a backup is one command. If you use git, the assistant's changes also show up as a reviewable diff.

2. Start read-only

Begin with tasks that only read: audit the vault, list overdue tasks, summarise the week. Let the assistant earn trust on things that cannot hurt.

3. Show the exact change, then ask

"I'll clean up your links" is not a plan. "In Podcast launch.md line 7, change [[Guest list]] to [[Guests]]" is. Require the exact edit before anything is applied, and require a clear yes.

4. Dry run first, and keep an undo log

Anything that moves or renames files should print a plan and change nothing until approved, never overwrite an existing file, and record what it moved so a single command can put everything back.

5. Do not let the model count

Language models miscount, lose their place in long lists and forget which items they already handled. Anything numeric or exhaustive (how many broken links, which tasks are overdue, what changed this week) should come from a script, and the assistant should explain the script's output. If a number is not from a script, treat it as a guess.

6. Make it say when it does not know

A good assistant reports "the cause is not visible in the vault" instead of inventing a reason a task slipped. Put that in the instructions file the assistant reads at the start (in Claude Code, a CLAUDE.md), along with the read-only default and the approval rules above.

7. Think about privacy

Claude Code sends what it reads to Anthropic to generate replies. Check Anthropic's current data terms, and keep genuinely sensitive notes (medical, legal, client-confidential) out of the folder you point it at. Scripts that only read files locally send nothing anywhere.
